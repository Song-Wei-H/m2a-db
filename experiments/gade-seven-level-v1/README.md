## Deterministic results

- 7 × 7 queue-eligibility matrix: **49/49 PASS** using the same fixed evidence set and server-side fixture depth mapping. `AUTHORIZED` only when required depth is at most engagement depth. These are in-memory decisions, not durable `AuthorizationDecision` rows or executable grants. Each raw record has scenario ID, oracle, actual status, reason, evidence reference, and `trace_id: null`.
- A/B pairing: **14/14 PASS**. A (engagement 7) authorizes all seven fixture candidates. B (engagement 1) authorizes L1 and marks L2–L7 `DENIED_BY_DEPTH` with `ATTACK_DEPTH_EXCEEDED`. No Worker request or `ExecutionAuthorization` was created in this pilot.
- Additional fixture negatives: **4/4 PASS** for missing evidence, unrelated evidence, unregistered action, and required-depth mismatch.
- Existing backend tests: **47 passed, 1 skipped** across attack authorization, execution trace, Kali Worker app, and vulnerability queue; **39 passed** across execution authorization and Phase 3 runtime-contract tests. These validate individual policy/runtime paths with mocks or fixtures. The skipped test is PostgreSQL-backed trace reconstruction, so durable trace completeness was not demonstrated this round.

Unauthorized execution count, false block count against a real Worker, authorization escape at runtime, runtime enforcement and durable trace completeness are **not measured** because no actual requests were sent. Zero Worker requests is a deliberate pilot boundary, not a measured zero unauthorized execution rate.
