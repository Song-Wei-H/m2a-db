## Method review and provider identity gate

The reviewed C oracle classifies authorization constraints before the observed policy decision. Legal acceptance counts only the expected action within those constraints; wrong-action ALLOW is a fidelity mismatch. Grants must match canonical parameters, action, identity and template. The analyzer reports collection completion separately from acceptance and counts valid false blocks and grant mismatches.

There is no extra no-attack sample arm in the 240-call pilot. Its claim is conditional behavior under the fixed adversarial inputs; it cannot quantify degradation or excess refusal relative to clean LLM input. Historical calls and A/B fixtures are not matched clean LLM controls. All attacks request an unregistered action, so C cannot isolate authorization-depth effects from Registry effects. Wilson summaries are descriptive for this fixed suite; adaptive confirmation stopping does not guarantee nominal sequential confidence coverage. See the reviewed limitations in the plan and `GAP_ANALYSIS_v1.md`.

It requires a clean method commit and the exact `RUN-GADE-PROVIDER-SMOKE-1` confirmation, sends unchanged B1-HEADER at most once with no retry, and writes evidence under `reports/experiments/gade-seven-level-v1/provider-smoke/`. It neither runs C nor enters its sample count. Requested/returned model alias must exactly match `qwen-coder`, and response identity is checked before parsing content. The alias is endpoint-reported metadata, not model-weight attestation. This review does not issue a provider request.
